---

## 一、问题陈述

### 用户反馈的 4 个直接问题
1. "命中事件"标题显示"邮箱地址 492条命中 492"——两个 492 重复。
2. 列表只显示 4 月数据，看不到最新（信号头部却写"最近 07/05"）。
3. 敏感值 `n15035344@qq.com` 多了 n；会话输入输出里搜不到这个邮箱。
4. "命中会话"看不懂；抽屉里看不到邮箱，也不知道和命中是什么关系。

### 调研中发现的更深问题
5. **语言问题**：满屏开发者黑话（conv/fact/evidence_group/工具回显/出现面/属实），安全岗和管理者看不懂。
6. **"属实"是废话**：用户要的是具体可核实的事实（次数/工具/时长/退出码），不是"属实"。
7. **聚合致命缺陷**：敏感数据信号按全局大类聚合（一条"邮箱暴露"永远存在），事件持续不断（真实库验证：相邻事件中位间隔 1.5 分钟，63% < 10min），"处理"后几分钟就复活，永远处理不完。
8. **只针对敏感数据设计**：初版方案只围绕邮箱，不是通用产品。13 种信号类型需要统一骨架。

## 二、用户与目标

**用户**：安全岗 + 团队管理者。非开发人员。

**打开一个风险信号时，心里问的 4 个问题**：
1. **什么风险**——发生了什么（一句话，说人话）。
2. **什么类型**——数据泄露 / 行为异常 / 执行错误 / 用量异常。
3. **是不是真发生了**——看上下文和证据自己判断（不靠系统生成的判断句）。
4. **上下文和证据**——在哪个任务、什么时候、出现什么、点进去看原文。

**关键决策（用户确认）**：真实性**不由系统在头屏自动判断**（"主要在查数据时带出来的"这种话用户看不懂）→ 改为**给事实 + 让用户点进去看上下文自己判断**。

## 三、聚合模型（最关键的架构决策）

### 3.1 现状问题（数据验证）

| 维度 | 现状 | 数据验证 |
|---|---|---|
| 敏感数据信号 | 全局按类型聚合（一条 `sensitive_content_exposure:email` 永远存在） | 252 次事件 / 88 天，相邻间隔中位 **1.5 分钟**，63% < 10min |
| "处理"有效性 | 处理后新 fact 进来 → snapshot_hash 变 → 自动复活成 needs_review | 永远处理不完 |

### 3.2 被否掉的方案（都用数据验证过）

| 方案 | 否决理由 |
|---|---|
| 生命周期 + "新增角标" | 角标永远亮（1.5 分钟就有新事件）|
| 切事件段（burst cooldown） | 1h 冷却切成 73 段，中位才 2 事件，大多是碎片 |
| 按出现面分流（tool=噪音/content=信号） | **用户纠正**：Agent 自主去拿 PII（grep/读凭证文件）本身就是风险，不能因为"在工具结果里"就当噪音 |

### 3.3 最终方案：按任务（会话）聚合

**数据验证**：email 252 次触碰分布在 **64 个会话**里：
```
27 个会话：1 次
29 个会话：2-5 次
 6 个会话：6-20 次
 2 个会话：>20 次
```

→ 按**任务**聚合 = **64 条可结案信号**（每条 = "某个任务里 Agent 触碰了 PII"），而非 1 条永远在涨的大类。

**为什么有效**：
- 每条信号 = 一个有界的任务级事件。任务结束 → 不再进新事件 → 稳定 → 可结案。
- 和其它信号类型一致（文件变更/卡循环/失败本来就按会话聚合，唯独敏感数据被做成了全局大类）。
- **所有 PII 触碰都保留**（不过滤、不降级），只是按任务归堆 → 用户能一条条处理。

## 四、信号生命周期

### 4.1 状态机

```
待处理 ──处理──► 已处理（覆盖到此刻）
                   │
      无新行为 N天 │     新行为进来
      ──自动关闭   │     ──► 不复活！只标"自上次处理以来新增 N"
                   │
                   └─► 已忽略（静音：N天 / 直到停止 / 永久）
```

### 4.2 核心规则

| 规则 | 说明 |
|---|---|
| **"已处理"稳定** | 处理时记水位线（时间 + 覆盖到的范围）。之后新行为**不改状态**，只挂"新增 N"角标 |
| **不自动复活** | 不再像现在这样 snapshot_hash 变就复活。已处理就是已处理 |
| **新行为 = 角标** | 新行为显示"自上次处理（T）以来新增 N"，用户决定再看 / 再处理 / 静音 |
| **静音** | 对反复出现的：忽略 N 天 / 直到停止 / 永久。静音期间不进列表 |
| **自动关闭** | N 天无新行为 → 自动已处理 |
| **列表默认** | 只列出：待处理 + 已处理但有新增。已处理无新增 / 已忽略：默认隐藏（可筛选） |

### 4.3 业界参考

- Sentry：issue 累计事件，resolved 稳定，new event 可重开（可配），ignore until N 天。
- BigPanda：重开窗口（60min 内复发=重开，外=新 incident）。
- PagerDuty：resolved 可重开。

## 五、详情页信息架构（通用骨架，13 类共用）

```
┌─ [类型·图标] [细项] ─────────── [严重度] · N次 · 最近 时间 ─┐
│                                                            │
│  一句话风险：用人话说"发生了什么"（带具体对象）             │
│  关键事实：按类型给可核实的具体数字（不是"属实"）           │
│                                                            │
│              [ 处理 ]  [ 已读 ]  [ 阈值设置 ⚙ ]           │
├─ 证据 · 出现记录 ── [筛选条] ─────────── < 1 2 3 … > ──┤
│  时间   关键列   来源/状态   任务名   [ 看原文 → ]        │
│  …（分页）                                                 │
└────────────────────────────────────────────────────────────┘
```

**只有两处按类型变化**：
1. **关键事实那行**：什么字段（卡循环=次数/时长/间隔；失败=退出码/错误；敏感=值/次数…）。
2. **证据列**：每条怎么画（敏感=值标签；失败=命令+退出码；文件=路径+增删；用量=token 数）。

**其余完全一致**（13 类共用一套 IA）。

## 六、人话词汇表

### 6.1 四大类型（替代 signal_kind）

| 人话名称 | 图标 | 对应 signal_kind |
|---|---|---|
| 数据泄露 | 🔓 | sensitive_content_exposure |
| 行为异常 | ⚠️ | destructive_operation, change_volume_anomaly, key_file_change, agent_loop_stuck, repeated_tool_failure |
| 执行错误 | ❌ | tool_execution_failure, tool_execution_timeout, workflow_step_failure, workflow_step_timeout |
| 用量异常 | 💰 | usage_spike, low_cache_hit_rate, unknown_usage_dominant |

### 6.2 禁用词 → 人话替换

| 禁用（内部术语） | 替换（人话） |
|---|---|
| sensitive_content_exposure | 数据泄露 |
| conversation / conv:73db | 任务（用任务名+时间） |
| fact / evidence_group / evidence_ref | （不出现，内部概念） |
| 工具回显 / 出现面 | （不出现；如需区分，用"Agent 读取文件时" / "用户输入" / "Agent 回复"）|
| 属实 / 持续属实 | （删掉，换成具体数字） |
| tool_context / exit_code | 工具名、退出码（在证据条目里用人话标） |
| decision_state | （不出现） |

## 七、各类型证据呈现（具体字段替代"属实"，全部已用真实库验证 ✅）

| 类型 | ❌ 废话 | ✅ 头屏具体事实（库里有） | 证据条目画什么 |
|---|---|---|---|
| **数据泄露** | ~~（不判断真假）~~ | 出现的**值**（去重）、**每个值几次**、**最近一次**。真实性由用户点进去看上下文 | 值标签 + 任务名 + 时间 + [看原文] |
| **破坏性操作** | ~~确实执行了~~ | **什么操作**（rm/git reset）、**N 次**、跨 **N 个任务**、最近一次 | 操作 + 对象 + 任务 + [看原文] |
| **卡循环** | ~~持续属实~~ | **调用 N 次**、**哪些工具**、**从几点到几点**、**平均多久一次**、最近一次 | 工具 + 命令 + "（无产出）" + 任务 + [看原文] |
| **工具反复失败** | ~~失败属实~~ | **什么工具**、**退出码**、**失败 N 次**、**错误摘要**、第一次/最近一次 | 工具 + 命令 + 退出码 + 错误 + 任务 + [看原文] |
| **文件大量改动** | ~~改动属实~~ | **改了 N 个文件**、**哪些目录**、哪个任务 | 路径 + 目录 + 任务 + [看原文] |
| **关键文件改动** | ~~改动属实~~ | **关键文件类别**（如"数据库迁移"）、**具体路径**、N 次 | 路径 + 类别 + 任务 + [看原文] |
| **用量突增** | ~~属实远超常规~~ | **单次调用 N 万 token**、超阈值 **N 次**、input/output 拆分 | token 数 + 会话 + [看原文] |
| **缓存命中率低** | ~~属实~~ | **命中率 X%**、输入 **N 万** token、仅命中 **N 万** | 命中率 + token 数 + 会话 |
| **超时** | ~~属实~~ | **什么命令**、**耗时 N 秒**、**阈值 N 秒**、退出码 124 | 命令 + 耗时 + 阈值 + 任务 + [看原文] |

**唯一小缺口**（诚实交代）：
- 用量/缓存的"平常多少"基线：单条信号里没有历史均值。**阈值做成界面可配**（用户确认）。
- 文件改动的增删行数：部分 fact 没记行数（projection 缺）。有就显示，没有就不显示。

## 八、交互模式

| 模式 | 设计 | 解决的痛点 |
|---|---|---|
| **头屏先结论** | 一句话风险 + 关键事实 + 动作。证据在下方 | 结构乱/没重点 |
| **按值/类型维度去重** | 敏感按值；失败按工具；文件按目录 | 内容重复 |
| **就地过滤** | 点"按任务▼"/"按值▼"→ 过滤证据列表，**不跳抽屉** | 命中会话应过滤 |
| **真分页** | `< 1 2 3 … 9 >`，无硬上限 | 命中事件无分页 |
| **最新在前** | 证据按时间倒序 | 只看到 4 月 |
| **[看原文→] 下钻** | 点进去看会话原文上下文；打不开时明确提示"该任务无可展示原文" | 查看会话打不开没提示 |
| **不自动判断真实性** | 头屏给事实，不生成"主要在查数据时带出来的"判断句；用户点进去自己看 | 真实性看不懂 |
| **证据条目标来源** | 每条标注"Agent 读取文件时" / "用户输入" / "Agent 回复"（从 fact_type/category 映射，用人话） | 帮用户判断（但不强制） |

## 九、阈值可配置

用户要求："在产品界面放开阈值设置参数，避免写死。"

**阈值设置面板 `[阈值设置 ⚙]`**：

| 类型 | 可配参数 |
|---|---|
| 卡循环 | 次数阈值、时长阈值（分钟）|
| 用量突增 | token 阈值 |
| 缓存命中率 | 命中率阈值（%）|
| 文件变更 | 文件数阈值、增删行数阈值 |
| 重复失败 | 次数阈值 |
| 敏感数据 | （可选）哪些类别算敏感 |

当前这些阈值写死在 builder 代码里，改为存 DB（如 effective_policies 表）+ 界面可编辑。

1. **后端：敏感信号改按任务聚合**（最大架构变更；改 `_build_sensitive_content_exposures` 的 signal_key 从 `object_type` → `conversation_ref`；改回填）。

## 附录：调研过程中用真实数据验证的关键结论

| 结论 | 数据支撑 |
|---|---|
| 邮箱 492 里 90%+ 是假阳性 | distinct 98 种写法里 90 种是 `@pytest.x` / `@app.get` 装饰器 + `test@example.com` + `\n` 前缀 |
